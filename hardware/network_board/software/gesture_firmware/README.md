# Gesture demo firmware for the second board

This directory contains the standalone RV32 firmware source and portable tracking logic for the second board. The firmware links within the 16 KiB OCR region with a 2 KiB minimum stack reserve; the current ELF, binary, and ROM lanes are generated locally. The CPU polls published 640×360 RGB888 frame tokens, schedules the capture ROI resampler and NPU, decodes the existing int8 output tensors, and classifies a left or right swipe. The input tensor is the NPU's 224×224 C32 image at `0x02129000`; every pixel is `[R,G,B,0×29]`, with 7,168 bytes per row. The CPU never runs an ML model.

The CPU-visible interfaces follow the integration map: NPU APB at `0xf8101000`, video/ROI APB at `0xf8102000`, gesture UART at `0xf8103000`, web controls at `0xf8104000`, and read-only model Flash at `0xf8105000`. The Flash registers are CTRL, ADDR, DATA, and STATUS at offsets 0, 4, 8, and 12. Reading DATA acknowledges one complete little-endian word and advances the Flash address by four bytes. The NPU address-offset CSR at `0x24` is programmed with `0x02000000`; the hardware adds it to every descriptor-driven AXI read and write address once.

`tools/build.bat` (Windows) and `tools/build_linux.sh` (Linux) package the genuine `weights_hw.bin` and `param_hw.bin`, then build the RV32 ELF and raw binary. The Linux script accepts an optional output directory; by default it writes to `build/linux/` and creates the four OCR ROM lanes under `build/linux/rom/` without overwriting the board project's active ROM files. The linker places the firmware in the 16 KiB OCR region at `0xf9000000`. `tools/package_model.py` validates both image lengths, computes CRC32 values, and writes a manifest and `model_crc.h`.

After synchronized DDR calibration, firmware reads the 24-byte `GMD1_LE32_HEADER_V1` header at Flash `0x00400000`. It accepts only the fixed version, payload sizes, and CRCs from `model_crc.h`. Weights stream from Flash `0x00401000` to DDR `0x02000000`; parameters stream from Flash `0x0050e000` to DDR `0x0210d000`. The CPU writes through its existing AXI-A DDR path and checks each payload CRC before setting `gesture_model_ready`; neither the input tensor at `0x02129000` nor capture buffers are written by the loader. SPI is read-only and never issues program or erase commands. A missing or invalid header, transfer timeout, or CRC failure leaves the model unready and keeps the existing volatile JTAG `load_image` path available. The JTAG Tcl writes the same DDR ranges and does not program persistent Flash.

The firmware ELF entry is `_start` at `0xf9000000`; the OCR image is 16 KiB padded into four 4 KiB ROM lanes by `tools/pack_ocr_rom.py`. The generated SoC RTL contains a direct CPU DBus path into AXI-A and no data-cache plugin or cache-maintenance interface. `fence iorw,iorw` orders model writes before CRC reads and NPU startup.

`gesture_return_send()` encodes LEFT/RIGHT as versioned semantic UART frames. Website UI actions and pointers arrive through the CDC/APB mailbox at `0xf8104000` and share a four-frame bounded queue, sequence allocator, CRC-16/CCITT-FALSE serializer, and 64-byte full-duplex UART at `0xf8103000`. The RX parser accepts only CRC-valid ACK frames matching the one outstanding web command. Each command keeps its own web token through queue, send, ACK, rejection, or 500 ms timeout; action commands are never automatically replayed. Service remains nonblocking and runs during model CRC scans and bounded ROI/NPU waits. J7 TX is GPIOL_04/B3 on physical pin 37 and RX is GPIOL_10/B5 on pin 38, both TL-bank 3.3V. ACK acceptance means A validated and handed the action to its input/scheduler; it does not promise frame-boundary commit or visible output. The existing Sapphire USB UART at `0xf8010000` remains dedicated to diagnostics. The APB map and command registry are documented in `docs/return_uart_protocol.md`.
