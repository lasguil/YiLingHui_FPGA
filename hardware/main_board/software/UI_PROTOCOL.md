# UI CPU/RTL protocol v2

## Commit and metadata

The existing VS mailbox is the sole commit and acknowledgement mechanism. `0x40` (`UI_DATA`) carries metadata; `0x48` (`UI_METRICS`) retains FPS BCD and valid; `0x44` (`UI_HINT`) remains the hand-marker position; `0x78` (`CATALOG_INFO`) carries actual model count in bits `[4:0]` and table count in `[11:8]`. CPU writes the metadata, catalog counts and three value words before requesting the regular VS commit. The renderer sees the snapshot atomically at that commit.

`UI_DATA` encodes page `[2:0]` (home 0, color 1, basic adjust 2, keep-color 3, RGB range 4), color mode `[4:3]`, displayed model index low bits `[7:5]`, selected table index low bits `[13:11]`, preserve `[17]`, range preset `[20:18]` (four named presets 0..3), pending `[21]`, paused `[22]`, input mode `[24:23]`, and view `[26:25]`. Model index high bits are `[27]` (bit 3) and `[31]` (bit 4); table index high bit is `[28]` (bit 3); camera vertical flip is `[29]`; full remote UI hide is `[30]`. Dynamic model/table counts are sent through the `0x078` catalog-info CSR.

The loader accepts only ready entries with the supported format and size. A model index becomes displayed only after a result generated by that model receives the normal VS commit acknowledgement. A failed package load attempts to restore the prior package; the displayed model index and image remain on the prior entry until a new model result is committed. All generated model and LUT indexes fit the widened UI metadata and 10-bit shared catalog RAM.

The color-table directory presents 13 choices: built-in neutral `IDENTITY` at slot 0, followed by all 12 generated LUT entries. LUT bytes are copied with the model bundle to DDR and loaded into the existing single shared curve memory through `sp_load_color_table()` and the IPX DMA; this does not add curve RAM. No CPU DDR reads or writes are used. A selected table index is presented in the UI metadata; result/table generation visibility follows the existing frame and VS-ack boundaries.

## Dynamic name catalog

The renderer uses one 10-bit-addressed, 8-bit character RAM. CPU writes `0x70` (`CATALOG_INDEX`) to set its byte index (low eight bits in `WDATA[7:0]`, high bits in `[9:8]`), then writes each character to `0x74` (`CATALOG_DATA`); each data write stores the low byte and increments the index. Names are left-justified and space-padded to 16 characters. The glyph ROM implements exactly uppercase A–Z, digits 0–9, space, hyphen, slash, and period; software converts lowercase letters to uppercase and rejects unsupported characters. The firmware limits model names to 10 visible characters and table names to 16.

## Numeric values

`0x64`, `0x68`, and `0x6c` carry eight contiguous 12-bit BCD values, least-significant slot first. Slots 0..5 remain available to the datapath and legacy RGB display state; keep-color shows OUT SAT in slot 0. Slots 6 and 7 always contain AI and FX. Unused slots are zero. Values cross 32-bit register boundaries as a single packed 96-bit stream. The UI exposes four named keep-color presets and no per-channel range editor.

AI and FX are 0..100%. SAT and OUT SAT are 0..200%; Q8 conversion is rounded as `(percent*256+50)/100`, respecting hardware maximum 512. Parameter changes remain pending until applied to a processing frame. Pausing stores edits without implying that the frozen result has changed. An independent UI-only VS commit can show pending controls without stalling the next processing frame.

Control availability follows the datapath: FX remains enabled for all four color modes; SAT is disabled while preserve is enabled or in grayscale/duotone modes; OUT SAT is enabled only with preserve enabled and a non-gray/non-duotone mode.

Fixed labels and wording remain in the PL ROM. The CPU supplies numeric fields and directory indexes.
