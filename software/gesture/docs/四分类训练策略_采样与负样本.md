# 四分类训练策略：分层采样、负样本与损失函数

> 适用模型：[G4Net v1](G4Net_v1_模型设计.md)。模型固定四类输出，训练策略不增加分类头或改变硬件算子。

## 1. 设计目标

固定类别顺序为 `0=手掌、1=一根手指朝上、2=拇指朝下、3=其他`（v4，定义见 [单模型方案](手势交互_单模型方案.md)）。
当前前三类分别有 6,882 / 21,024 / 7,028 张，其他有 142,190 张（HaGRID 部分 118,801）。
手部过小（手占画面面积 < 0.03）的 1,675 张已从目标类划入其他，见 [数据说明](../dataset/README.md)。
后续其他类还将引入外部数据集和目标摄像头背景，不能直接拼接全部图片后随机采样。

需要分别控制三种不均衡：

| 层面 | 问题 | 处理方式 |
|---|---|---|
| 四类之间 | 其他类数量多，三个目标类被淹没 | 固定 batch 类别配额 |
| 其他类内部 | 某个外部数据集或源子类数量过大 | 按语义池、来源、子类分层抽样 |
| 样本难度 | 大量简单背景与少量易误触发图片并存 | CE 基线、focal 对照、审核后的困难样本回放 |

本方案的配额、训练步数和超参数都是实验起点，最终按真实摄像头验证结果选择，不视为已验证的最优设置。

## 2. 数据索引与划分先于采样

训练索引至少记录：`sample_id、path、class_id、source_dataset、source_subclass、semantic_pool、duplicate_group、split、label_review_status`。
每次数据扩充保存索引版本、来源记录与 split 清单；checkpoint 记录索引及采样配置指纹。

**划分口径（已定）**：公开数据按图片做分层随机划分，固定 seed 并保存清单。现有图片来自 HaGRID 分类镜像，抽取时未保留人物/场次信息，恢复到人物粒度的把握不大，因此**不把按人物划分作为前置条件，本版也不做这项恢复**。自采摄像头数据的场次由我们自己记录，按录制场次分组。

1. 公开数据：按类别分层随机划分 train/val/test，固定 seed，清单入库并记录指纹。
2. 自采摄像头数据：按录制场次分组，同一场次不跨集合。
3. 采样器只访问 train。验证、测试不做类别平衡、不做困难样本回放，固定名单。
4. 外部数据与旧数据一起检查重复；原数据有官方 split 时保留来源信息并核查跨源泄漏。
5. 外部数据不能一律标为其他：清楚出现目标手势的图片应正确标注或排除；目标手势与非目标物体共存时也不能直接当负样本。
6. `no_gesture` 不能等同于无手，必须按实际内容审核语义池。手部太小、模糊或多手标签冲突的图片单列审核，不自动作为“困难其他”。

> **已知局限**：图片级划分无法排除同人物、同背景的近重复帧跨集合，公开数据的验证/测试指标因此偏乐观。它只用于开发期的相对比较（选损失、选结构、调超参），**不作为泛化结论，也不作为验收依据**；最终验收以真实摄像头独立数据为准，见 §7。

保持整帧输入与当前模型预处理。增强裁掉目标后不能继续沿用原目标标签。

## 3. 分层采样

### 3.1 四类配额

首轮 batch=64，建议固定：

| 类别 | 数量 | 占比 |
|---|---:|---:|
| 握拳 | 12 | 18.75% |
| 一根手指朝上 | 12 | 18.75% |
| 拇指朝下 | 12 | 18.75% |
| 其他 | 28 | 43.75% |

其他类内部变化更丰富，因此首轮给它高于单个目标类的配额，但不让其占比随图片总数无限增长。
可与每类 16 张的等量方案做独立采样消融；比较时保持模型、损失、总训练步数和数据划分一致。

目标类内部按来源及源子类轮换；一类多子类时（如 like/one/mute）须逐个覆盖。
优先在各分组内无放回轮换，耗尽后重洗牌；分组不足一个批次时允许有放回，并记录重复率。

### 3.2 其他类的内部配额

采用“类别 → 语义池 → 来源/源子类 → 图片”的抽样层级。初始示例：

| 其他类语义池 | batch 内配额 | 内容 |
|---|---:|---|
| 非目标手势与手部 | 14 | HaGRID 其他手型、非目标手部姿势等；保留不同源子类覆盖 |
| 同域背景与日常干扰 | 8 | 目标摄像头的无手背景、人脸、手臂、拿物体等经审核的非目标画面 |
| 外部数据 | 6 | 其他数据集的经审核背景、物体及非目标手势，按来源继续分组 |

语义池互斥地记录在索引中；不同来源的同类内容保留 source 标记。
池内可先按来源/源子类等概率选择，再从该组抽图片，避免大来源垄断配额。

某池为空时只对已存在的 train 池重分配配额，保证其他仍为 28 张，记录实际比例和缺失覆盖；不得借用 val/test 填补。
后续新增数据只扩充对应池及可选来源，不自动改变外层比例。训练日志记录每类、每池、每来源的曝光数和独立图片数。

### 3.3 固定训练预算

定义一个虚拟 epoch 为 **500 个 optimizer step**，每步 batch=64，即 32,000 次样本曝光；这不是全数据遍历。
首轮最多 80 个虚拟 epoch，共 40,000 步；warmup 为前 5 个虚拟 epoch，其后 cosine。
若按验证结果提前停止，记录实际步数；用于损失消融的正式比较保持相同最大预算，并比较相同步数的结果。

数据池变大后仍保持相同 step 预算，增加的是轮换多样性，不因“全量遍历”的 epoch 变长而暗中增加训练计算量。
不再采用旧草案的“每类每 epoch 抽 7,000 张”规则。

## 4. 损失函数：先 CE，再对照 focal

第一组实验使用相同索引、batch 配额、初始化 seed、增强、优化器与训练步数，只改变损失：

| 实验 | 损失 | 初始参数 |
|---|---|---|
| A | softmax CrossEntropy | 无类别权重，label smoothing=0 |
| B | softmax 多分类 focal | gamma=1，各类 alpha=1 |
| C | softmax 多分类 focal | gamma=2，各类 alpha=1 |

四类互斥，使用单个四类 softmax 的目标概率 `p_y`：

```text
loss_i = -alpha[y_i] * (1 - p_y_i)^gamma * log(p_y_i)
loss = mean(loss_i)
```

gamma=0、alpha=1 时退化为普通 CE。实现时从 `log_softmax` 取目标 log 概率，不手工计算不稳定的 exp/log 链；focal 系数参与梯度，不 detach。
不直接套用多标签 sigmoid focal；不把已经乘过类别权重的 CE 通过 `exp(-loss)` 当作 p_y。

Focal 降低容易分对样本的相对贡献，让训练更关注难例；它最初针对密集检测中的简单负样本问题提出，不保证在本四分类任务上优于 CE。[原论文](https://arxiv.org/abs/1708.02002)

初期不同时叠加强逆频率权重、复杂采样和困难回放。先通过 A/B/C 明确 focal 是否有收益，再单独调整其他因素。
持续高损失可能来自错标签、模糊图像或域差，不一定是值得反复强化的有效难例；使用 focal 前后均需审核失败样本。

其他建议起点沿用模型设计：AdamW、学习率 3e-4、weight decay 1e-4。若首轮资源允许，使用多个固定 seed 复核候选差异；比较时不修改验证集。

## 5. 困难负样本回放

完成 CE/focal 基线比较后，用选定基线扫描 **train 中的其他类**：

1. 保存高分误判成三个目标类的样本，附预测类别、目标分数、与其他分数的差值、来源和索引版本。
2. 先人工复核标签并去除重复、无效或歧义样本；若实际是目标类，修正标签，不能继续按负样本训练。
3. 审核后的有效难例进入回放池，起点最多占其他类配额约 20%，即每 batch 最多 6 张。
4. 回放占用该图片原语义池/来源的配额，避免以“难例”名义让单个外部来源重新垄断其他类。
5. 其余其他样本仍随机轮换；按版本刷新、去重和限制单图曝光，不反复训练一小撮异常图。

回放实验从同一基线 checkpoint 分支，与不使用回放的对照进行相同步数、相同学习率的继续训练。
验证和测试失败图只用于评价与分类分析，不能回流本轮训练；需要纳入新一版训练的数据，应另建独立留出集并记录版本，不能继续沿用原测试成绩作泛化证据。

## 6. 外部数据扩充与域差

- 始终混合旧目标样本、旧负样本和新来源；不只使用新增负样本微调。
- 维护同域负样本覆盖，统一解码/预处理，避免“目标全来自 HaGRID，其他全来自另一来源”的背景捷径。
- 分来源报告指标，核查水印、边框、分辨率、压缩和背景是否形成可投机的分类线索。
- 新来源先审核标签与分组，再做“加入前/加入后”的等预算对照；检查三个目标类召回是否下降。
- 其他是有限训练集合中的兜底类，不保证覆盖所有未见图像；真实摄像头留出测试和 CPU 接收阈值仍需验证。

## 7. 验证、阈值和 checkpoint 选择

保留两类独立评价：公开数据按图片分层留出，只用于四类识别的开发期相对比较；目标摄像头按会话留出，用于部署域中的误报与响应，是唯一可作为验收依据的评价。
公开数据的自然比例不等同于真实设备中“多数时间无手”的比例，不混成一个总准确率掩盖差异。

必须报告：

- 四类混淆矩阵、逐类 precision/recall、macro-F1。
- 其他被误判成任一目标类的比例：`目标类误报数 / 真实其他样本数`，并拆分误报去向和数据来源。
- 不同距离、光照、手占画面比例，以及无手、非目标手势、多手冲突的分组结果。
- CPU 接入后的每小时误触发次数、有效操作召回与触发延迟；逐帧误报不能直接替代事件误触发率。

初期并列保存验证 macro-F1 最优和误报/召回折中候选，不只按 overall accuracy 选模型。
在产品召回下限明确后，按“满足各目标类召回下限时，其他误报率更低”的口径选择最终 checkpoint 和接收阈值。
当前 `target_recall_floor` 取 0.8（2026-10-15 由 0.9 下调，取值属产品判断）。

训练重采样改变了类别先验，softmax 数值不能直接当已校准的部署概率。用真实摄像头验证集确定接收规则，例如目标为最高分且与次高类分差达到阈值，否则不触发事件。
阈值只在验证集选择；测试集用于冻结模型和阈值后的最终评价。INT8 转换后重新核查四个共尺度输出、阈值和饱和行为。
