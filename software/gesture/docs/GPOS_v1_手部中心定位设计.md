# GPOS v1 结构设计（手部中心定位）

**状态：结构已实现并通过 CUDA 检查；训练已在服务器 GPU1 启动；INT8 导出与板上接口未实现。**

`gpos_v1` 是**独立任务、独立模型族**，不是 `g4net_v4` 的下一版：它不输出四分类，只输出手部中心。
两者共用同一套身体的前 5 块（stem…ds4），所以权重形状兼容，但**几何与输出语义不同，checkpoint 不能互换**。

要解决的是动作判定方式：`g4net_v4` 用"手掌 / 一根手指朝上 / 拇指朝下"三个静态姿态直接定义动作，
`gpos_v1` 改为**输出手部中心**，由 CPU 跟踪位置序列判动作（上翻 / 下翻）。
位置比姿态稳，而且"向上 / 向下的位移"本身就是动作，不需要模型去记"什么姿势代表上翻"。
没手的图靠同一张热图表达：**整张图无峰**。

结构以 [configs/gpos_v1.json](../configs/gpos_v1.json) 与 [src/model.py](../src/model.py) 为准，
统计与 CUDA 检查见 [reports/gpos_v1.json](../reports/gpos_v1.json)。

## 1. 与 g4net_v4 的差别

| | g4net_v4（四分类） | gpos_v1 |
|---|---|---|
| 输入 | 3×192×192（方形） | **3×144×256（16:9）** |
| 网络体 | stem…ds9 + 1×1(96) | **stem…ds4（在抽头处截断）** |
| 输出 | GAP + FC → 四类 | **1×1 conv(32→1) → 18×32 热图** |
| 类别表 | 四个输出类 | 无输出（表仍在，供索引与采样使用） |
| MAC/帧 | 9,685,824 | **8,363,520（−13.6%）** |
| 训练参数 | 29,716 | **4,530（−85%）** |
| INT8 权重 | 27,984 B | **4,080 B（−85%）** |
| 特征 A/B arena | [110592, 147456] | 不变（[reports/gpos_v1.json](../reports/gpos_v1.json)） |

**为什么能截断**：位置头挂在 ds4 上，ds5/ds6/ds7/ds8/ds9 与 96 通道头都在它**下游**。
四分类时它们有用（GAP 要读末级特征图），position-only 时它们拿不到任何梯度，
profiler 的 CUDA 检查直接把这一点暴露成"参数没有梯度"的断言失败。
截掉它们省下 1.42 MMAC 与 25,186 个参数，**没有精度代价**——那些层本来就不参与输出。

## 2. 逐层结构

| 块 | 类型 | 输出 CHW | stride | MAC | 权重 | RF |
|---|---|---|---|---:|---:|---:|
| stem | conv 3×3 | 16×72×128 | 2 | 3,981,312 | 432 | 3 |
| ds1 | DW+PW | 24×36×64 | 4 | 1,216,512 | 528 | 7 |
| ds2 | DW+PW | 24×36×64 | 4 | 1,824,768 | 792 | 15 |
| ds3 | DW+PW | 32×18×32 | 8 | 566,784 | 984 | 23 |
| ds4 | DW+PW | 32×18×32 | 8 | 755,712 | 1,312 | 39 |
| **position** | **1×1 conv** | **1×18×32** | **8** | **18,432** | **32** | **39** |

合计 **8,363,520 MAC/帧**：15 fps 需 125.5 MMAC/s、30 fps 需 250.9 MMAC/s，
按 8 DSP @100 MHz 每拍 1 MAC 的容量假设分别是 15.7% / 31.4%。

## 3. 三个设计取舍

**抽头在 ds4（stride 8）。** 画布 256×144，1 输入 px = 画面 5 px，stride 8 一格 = **画面 40 px**；
末级 stride 32 一格是 160 画面 px，比一次上翻的位移还大，不能用作位置。
ds4 处感受野 39 px（约画布高度 27%），而实测训练图里手中位高 105 px、p10 为 52 px，上下文足够。
更浅的 stride 4（ds2 之后）精度更高但特征更浅，成本 +55,296 MAC，作备选。

**1×1 无激活。** 热图在无手处必须能降到 0 以下，ReLU6 会把"此处没有手"那半边截掉。
位置头因此用 `ConvBN`（[src/model.py](../src/model.py)），这是它与身体唯一的算子差异；
sigmoid 留给导出（NPU 已有 `ngm_sigmoid_lut`），层级不做。

**整张热图送 CPU，不在片上算 argmax。** CPU 本来就要做时序状态机，而整张图免费给它三个信号：
峰值 = 有无手、soft-argmax = 连续坐标、能量和 ≈ 手的大小。带宽 576 B/帧，30 fps 下 17 kB/s。
片上加 soft-argmax 需要加权求和与除法，逻辑量大于把 576 字节送出去。

## 4. 输出契约

| 输出 | 形状 | 约定 |
|---|---|---|
| 热图 | 1×1×18×32（576 格） | logit → sigmoid LUT → INT8，整张回传 CPU |

- **presence**：峰值超过阈值即认为有手。阈值在验证集上按最佳 F1 选，随 checkpoint 一起记录。
- **中心**：soft-argmax，坐标以画布归一化（与标签同约定）；映射到画面是纯缩放
  （16:9 → 16:9，无裁剪、无灰边）。阈值建议定义在**画面像素**上，换画布尺寸时不必重标定。

## 5. 板上（NPU）改动清单

1. **加一层**：1×1 PW 卷积，32→1 通道，BN 折叠，**不带 ReLU6**，出层接 sigmoid LUT。
   与现有 PW 层同类，只是层描述里的激活字段需要允许"sigmoid / 无激活"这一档。
2. **抽头紧跟 ds4 执行**：源图就是流里刚算出的激活（18,432 B），**不需要额外常驻**，
   只多 576 B 热图缓冲（`position_head.extra_arena_int8_bytes`）。
3. **多一条 576 B 读数通道**：v4 是 4 个 INT16 分数。**注意 position-only 没有 GAP、没有 reduce**，
   尾部 DRAIN 那套"对末级特征图做规约"的逻辑在这条路径上不需要参与——
   这是本次设计里唯一需要 RTL 侧确认的地方（把某一层整图送出而不是规约）。

## 6. 训练方法

**数据与损失**：输入 256×144 的 16:9 裁切图 + 教师中心点（§7）。目标是中心处 σ=1 格的高斯，
无手图全零；损失是 penalty-reduced focal（α=2、β=4），**按手数归一**（一只手的贡献为 1）。

| 项 | 取值 | 理由 |
|---|---|---|
| 目标峰归一化 | 缩放使最近格 = 1 | 见坑 1 |
| 头初始偏置 | BN 权重 0.01、偏置 −4.6（sigmoid ≈ 0.01） | 见坑 1 |
| 几何增强 | **只开水平翻转**（cx → 1−cx），旋转 / 缩放关闭 | 旋转与缩放会移动手，标签必须同步变换，否则是静默的标签污染；`src/data.py` 对这两个选项**直接报错拒绝** |
| 优化器 | AdamW，lr 1e-4，weight decay 1e-4 | 比四分类的 3e-4 低：热图目标更敏感 |
| 调度 | 500 步/virtual epoch，warmup 1 个、共 80 个（40,000 步） | warmup 从 5 个缩到 1 个：头很浅，5 个 epoch 等于 2,500 步空转（实测 warmup 内 AUC 一动不动） |
| 采样 | 沿用 v4 的分层配额 | 批次里有手/无手比例稳定（约 73% 有手） |
| 选点 | `best_presence.pt`（最高 presence AUC）+ `best_centre.pt`（召回 ≥0.95 的阈值下中心误差最小） | 漏掉的手没有中心，所以中心误差只在满足召回下限的点之间比较 |
| 目标锐度 σ | 1.0（参考值）；σ=0.5 的对照已跑 | **对照没有收益**：σ=0.5 在 4,500 步时 AUC 0.813 / 中心 19.1，与 σ=1.0 同期持平。平台是结构性的，不是目标锐度 |

**坑 1：模型会塌成"整张图恒定低概率"。** 第一次训练 5,000 步后 presence AUC 0.44（低于随机）、
logit 范围 −50…0.91、峰只有 0.47——模型学会了"到处都不出手"。原因是背景项有 571 格，
正样本只有一个高斯塔：目标峰值若只有 0.6、又按"峰值簇格数"（5）归一，正样本的拉力被淹没。
修法：目标峰值缩放到 1（最近格恰为 1，仍保留连续偏移的**形状**，soft-argmax 照样读亚格位置）、
按**手数**归一、给热图头 −4.6 的初始偏置。修完 300 步内 AUC 从 0.51 升到 0.70。

**坑 2：目标高斯差半格。** 单元格 `k` 的中心在"从左边量起"的 `k+0.5` 处，而高斯是按格索引画的，
所以要减 0.5；漏掉这一步就是固定 0.5/32 画布宽的偏移（**720p 画面里 20 px**）。
单元检查（2000 个随机中心的往返）现在把误差压到 x 0.16 px / y 0.42 px，不加这个检查很难发现。

**收敛曲线**（服务器 GPU1，batch 64，训练日志里的数字）：

| step | presence AUC | presence F1 | 中心误差中位（画面 px） |
|---:|---:|---:|---:|
| 500 | 0.673 | 0.678 | 125 |
| 2000 | 0.808 | 0.731 | 112 |
| 8000 | 0.827 | 0.738 | 86 |
| 26000 | 0.830 | 0.737 | 105 |

presence 在 2,000 步内就起来了，中心误差在 8,000 步后进入 17–21 画布 px 的平台。

**坑 3：阈值扫描从"中位数"起步，把高召回工作点和高 F1 都挡住了。** 选点与指标都用
"在峰值的分位数网格上扫阈值"，而网格原来是 `linspace(0.5, 0.999)`——即最低只到峰值的**中位数**：
召回 0.95 需要阈值落在峰值第 5 百分位以下，于是永远扫不到，
`centre_at_recall_floor` 全是 null、日志里的 F1 也被压低。改成从最小峰值的半处扫到最大峰值后
（`_threshold_grid`），同一 checkpoint 的 val 结果是：

| 指标 | 值 |
|---|---|
| presence AUC（val 8,496 帧，其中 6,526 有手） | **0.830** |
| 部署阈值 / 召回 / 精确 / F1 | **0.257 / 0.952 / 0.838 / 0.891** |
| 中心误差（两方都判有手的 6,211 帧） | 中位 **21.8 画布 px = 109 画面 px**；p90 218 画面 px；均值 121 |
| 分轴 | x 均值 19.1 px、y 均值 11.3 px（y p90 24.7）——**误差是各向异性的，纵向更准** |
| **静止抖动**（同一只手，7 个近同输入：±1 px 位移、±3% 亮度） | **x 1.12 / y 0.57 画布 px = 5.6 / 2.9 画面 px**（p90 1.75 / 0.99） |
| 教师自身重复性（同一张图 ±1 px 位移） | 0.50 / 0.38 画布 px（p90 0.77 / 0.65） |

**这三行放在一起才是结论**：教师的标注**非常稳**（0.5 画布 px），所以学生的误差不是标签噪声；
学生的**绝对误差大（约 109 画面 px）但抖动极小（约 3–6 画面 px）**——
也就是说残留的主要是**偏差**而不是噪声。对"跟踪位置序列判上翻/下翻"来说，
判据是位移/速度的**差分**，常量偏差会被消掉，而抖动直接决定阈值能否设得住。
因此这个模型**已经能支撑滑动判定**；它不支持的是"指哪儿是哪儿的绝对指向"。

**为什么中心精度上不去**（诊断拼图 `tmp/gpos_diagnostic.png` 显示预测是一大片弥散斑、
峰值落在"手的大致位置"）：教师框有 **30.5% 贴到裁切边界**，这些手的"中心"是可见部分的中心，
视觉上并不唯一；模型对这类样本只能学出一个折中的弥散响应。
想再往上推的选项有两个：把贴边样本从**中心监督**里剔除（打标侧一个开关），
或把抽头提到 stride 4（+55k MAC）换更细的格子。两条都还没做。
